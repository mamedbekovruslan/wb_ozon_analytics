# 002. Фильтры в URL

- **Статус:** готово
- **Дата:** 2026-11-05
- **Ветка:** `feat/url-filters`
- **Связанные ADR:** [0007](../adr/0007-роутинг-и-фильтры-в-url.md), [0003](../adr/0003-feature-sliced-design.md), [0008](../adr/0008-модель-угроз.md); новый ADR-0015 «Формат фильтров в URL» (дополняет 0007)

## Цель

Продавец выбирает период, площадку и категории один раз — и выбор переживает перезагрузку страницы, кнопку «Назад» и пересылку ссылки коллеге. Фильтры общие для всех страниц; данные будущих блоков (KPI, график, топ, остатки, заказы) запрашиваются по ним.

## Пользовательские сценарии

- Как продавец, я хочу переключать период пресетами (7, 30, 90 дней, квартал, год), чтобы быстро сравнивать отрезки.
- Как продавец, я хочу смотреть только WB, только Ozon или обе площадки и только нужные категории.
- Как продавец, я хочу включать и выключать сравнение с прошлым периодом.
- Как продавец, я хочу отправить ссылку коллеге, и он увидит те же фильтры.
- Как продавец на телефоне, я хочу настраивать фильтры в выезжающем снизу листе и видеть краткую сводку выбранного.

## Модель фильтров

**Параметры URL** (значение по умолчанию в URL не пишется):

| Параметр | Значения | По умолчанию | Смысл |
|---|---|---|---|
| `period` | `7`, `30`, `90`, `q`, `y` | `30` | пресет периода |
| `from`, `to` | `ГГГГ-ММ-ДД` | — | свой период; если заданы оба и валидны, `period` игнорируется |
| `mp` | `wb`, `ozon` | все площадки | площадка |
| `cat` | id категории, повторяется: `?cat=shoes&cat=sports` | все категории | категории |
| `cmp` | `0` | сравнение включено | `cmp=0` — сравнение выключено |

Пример: `/dashboard?period=7&mp=wb&cat=shoes&cat=sports&cmp=0`. Значения в URL — обычный текст (`mp=wb`), а не JSON (`mp=%22wb%22`).

**Расчёт дат.** «Сегодня» — `today` из `/api/meta` (данные за сегодня неполные, поэтому пресеты заканчиваются вчера — как в макете: сегодня 04.11, период 05.10–03.11). Конец `end` = сегодня − 1 день.
- `7` / `30` / `90`: начало = `end` − (N − 1) дней;
- `q` (Квартал): начало = первый день квартала, в который входит `end`;
- `y` (Год): начало = 1 января года, в который входит `end`;
- начало не раньше `historyFrom` из `/api/meta`.

**Свой период** (`from`, `to`) валиден, если обе даты существуют, `from` ≤ `to`, `from` ≥ `historyFrom`, `to` ≤ сегодня. Иначе применяется пресет из `period`, если он валиден, иначе «30 дней» (AC-7).

**Прошлый период** — той же длины, непосредственно перед текущим (`docs/domain.md`).

## Состояния

- Загрузка: AC-22 — скелетоны `--skeleton` на месте текстов дат и сводки категорий, без шиммера.
- Пусто: не применимо — у фильтров всегда есть значение (по умолчанию).
- Ошибка: мусор в URL → значения по умолчанию (AC-7, AC-8); ошибка `/api/meta` → AC-22.

## Данные и API

- `/api/meta` (уже есть): `today`, `historyFrom`, `categories` — для расчёта дат и подписей категорий. Добавляется поле `categories[].productCount` (AC-24) — число товаров справа в списке категорий, как в макете; правка фейкового API (`mocks/handlers`) и схемы `entities/marketplace`.
- Новых эндпоинтов нет. AC-16 — функция `filters → URLSearchParams` для будущих запросов `/api/kpi`, `/api/sales-daily` и т. д.; ключи TanStack Query будут строиться из разрешённых фильтров (ADR-0007).

## Безопасность

- **T4** (мусор и подделка в URL): все параметры проходят zod; невалидное → значение по умолчанию (AC-7…AC-10). Значения из URL в разметку как HTML не попадают — только как текст React.
- `Referrer-Policy` уже не передаёт URL с фильтрами на чужие сайты.
- Новых зависимостей нет; в `localStorage` ничего не пишется (T9).

## Не входит в задачу

- Календарь своего периода — фича 2b (до неё кнопка-диапазон не активна, AC-23).
- Шапка, навигация между страницами, нижние табы — фича app-header (перенос фильтров при переходах проверяется там).
- Запросы данных по фильтрам и состояние «нет данных» — фичи KPI, график, топ и др.
- Генерация данных в Web Worker — фича 2a.
