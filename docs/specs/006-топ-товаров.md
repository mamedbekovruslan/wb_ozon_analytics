# 006. Топ товаров

- **Статус:** готово
- **Дата:** 2026-11-07
- **Ветка:** `feat/top-products`
- **Связанные ADR:** [0003](../adr/0003-feature-sliced-design.md), [0005](../adr/0005-css-modules-и-токены.md), [0010](../adr/0010-контракт-api-и-адаптеры.md), [0015](../adr/0015-формат-фильтров-в-url.md)

## Цель

Под графиком продаж продавец видит десять товаров, которые за выбранный период принесли больше всего, — с выручкой, заказами, % выкупа и прибылью. Можно переключить, по какой метрике строится топ: самые продаваемые по заказам, самые прибыльные, с лучшим выкупом.

## Пользовательские сценарии

- Как продавец, я хочу видеть, какие товары дают основную выручку за период.
- Как продавец, я хочу найти самые прибыльные товары и товары с лучшим % выкупа.
- Как продавец, я хочу видеть, на какой площадке и в какой категории продаётся товар.
- Как продавец на телефоне, я хочу просматривать топ карточками и менять сортировку одной кнопкой.

## Сортировка

| Ключ блока | Колонка / подпись | Параметр `sort` API | Подзаголовок |
|---|---|---|---|
| `revenue` (по умолчанию) | Выручка | `revenue` | `по выручке за период` |
| `orders` | Заказы | `orders` | `по заказам за период` |
| `buyoutRate` | % выкупа | `buyoutRate` | `по % выкупа за период` |
| `profit` | Прибыль | `profit` | `по прибыли за период` |

- **Метрика** (ключ) уходит в запрос: топ-10 **по этой метрике** приходит с сервера (`/api/top-products?sort=…&limit=10`). Решение пользователя 2026-11-07.
- **Направление** (`desc` / `asc`) — только порядок тех же 10 строк на клиенте, без нового запроса. `asc` — порядок ответа наоборот; при сортировке по % выкупа товары без значения (`buyoutRate: null`) остаются в конце, при остальных метриках разворачиваются вместе со всеми (уточнено 2026-11-07 по вопросу `qa`). Подзаголовок при `asc`: `по выручке, по возрастанию за период` (как в макете).
- **Номер `#`** — позиция строки в показанном порядке (1…N), как в макете.
- Сортировка — состояние блока, не URL: после перезагрузки снова «по выручке», по убыванию. Решение пользователя 2026-11-07.
- **Таблица (≥ 640):** клик по заголовку другой колонки — эта метрика, по убыванию; по активной — смена направления (убывание ↔ возрастание).
- **Карточки (< 640):** кнопка в шапке блока перебирает метрики по кругу `revenue → profit → orders → buyoutRate → revenue`, всегда по убыванию (как в макете).

## Состояния

## Дизайн и адаптивность

- **Макет-референс:** `reference/Dashboard.dc.html` (секция `top-h`, состояния `loading` / `empty` / `error`, раскладки `desktop` / `tablet` / `mobile`), `reference/Guidelines.dc.html` (строка таблицы: hover, заголовок с сортировкой), `DESIGN_SPEC.md` § 2, § 4 «Таблица», «Мобильные карточки», § 5.
- **1440:** таблица на всю ширину карточки; **768:** та же таблица, мин. ширина 680, прокрутка по X, название до 260; **375:** карточки + кнопка сортировки 44.
- **Порядок на дашборде:** KPI → график → топ. В фиче 6 график и «Скоро закончится» встанут в одну строку на ≥ 1200; топ останется на всю ширину ниже.
- **Решения вне макета:**
  - метрика сортировки грузит новый топ с сервера, направление — порядок тех же строк (пользователь, 2026-11-07);
  - сортировка — в состоянии блока (пользователь, 2026-11-07);
  - текст ошибки: заголовок из макета + «Проверьте соединение и повторите. Остальные блоки работают.», как у графика; в макете — «Сервер вернул ошибку 500. Мы уже повторяем запрос.», но сами мы не повторяем, а причина бывает разной (пользователь, 2026-11-07);
  - **согласовано 2026-11-07:** при смене метрики старые строки остаются до ответа (AC-9) — иначе нажатая кнопка-заголовок исчезает вместе с таблицей под скелетоном и фокус клавиатуры теряется; в макете этого случая нет;
  - **согласовано 2026-11-07:** «% выкупа» без завершённых заказов (`null`) — «—» (в макете значение есть всегда);
  - **согласовано 2026-11-07:** «Арт.» — `sku` (артикул площадки: `nmId` у WB, `sku` у Ozon), как числа в макете (`184523671`); артикул продавца `offerId` не показываем.
- Фото товаров нет — заглушка-иконка из макета.
- **Таблица — `border-collapse: separate`, линия строки на `td` с `box-sizing: border-box`** (решение пользователя 2026-11-07): в макете `collapse` и линия на `tr`, но так линия делится между строками пополам и шапка выходит 36,5 px вместо 36. Внешне разницы нет.
- Полоса прокрутки таблицы — как в макете (`.scroll`: 10 px, бегунок `--border-strong`, радиус 8, рамка 2 px `--surface`); видна на 640–730 px.
- У таблицы доступное имя — заголовок секции (`aria-labelledby`); в макете нет, вид не меняется (ревью).

## Решения реализации

- **Обычный `<table>`, без TanStack Table** (AGENTS.md § 2): 10 строк, сортирует сервер, направление — разворот массива; библиотека не нужна. TanStack Table/Virtual придут со страницей «Заказы».
- **Прежние строки при смене метрики** — `placeholderData` в `useTopProducts`: прежние данные отдаются, только если совпадает часть ключа без `sort`; при смене фильтров — скелетон. Пока грузится новая метрика, прежние строки раскладываются по новой сортировке — кратковременно, под `aria-busy` (ревью, правка не нужна).
- **Таблица или карточки** — по `matchMedia` (`useMediaQuery(MOBILE_QUERY)`), как у графика: на телефоне таблицы нет в DOM.

## Данные и API

- `/api/top-products?from&to&mp&cat&sort&limit` (есть, spec 001): `items[]` — `sku`, `name`, `offerId`, `marketplace`, `category`, `revenue`, `ordersCount`, `buyoutRate | null`, `profit`. Схема `topProductsResponseSchema` в `entities/product` (есть). Новых эндпоинтов и полей нет.
- `/api/meta` (есть) — даты периода через `useFilters`, названия категорий.

## Безопасность

- Ответ `/api/top-products` проверяется zod-схемой (`apiGet`); невалидный ответ — состояние ошибки (AC-16).
- Названия товаров выводятся как текст React; `dangerouslySetInnerHTML` не используется; в `localStorage` ничего не пишется. Новых зависимостей нет.

## Не входит в задачу

- Фото товаров, переход к деталям товара по строке.
- Выбор числа позиций (не 10), пагинация топа.
- Хранение сортировки в URL.
- Сортировка по возрастанию на телефоне (в макете только перебор метрик).
- Экспорт топа (фича 8).
