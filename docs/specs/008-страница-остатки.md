# 008. Страница «Остатки»

- **Статус:** готово
- **Дата:** 2026-11-07
- **Ветка:** `feat/stocks-page`
- **Связанные ADR:** [0002](../adr/0002-стек.md) (TanStack Virtual), [0003](../adr/0003-feature-sliced-design.md), [0005](../adr/0005-css-modules-и-токены.md), [0007](../adr/0007-роутинг-и-фильтры-в-url.md), [0010](../adr/0010-контракт-api-и-адаптеры.md), [0015](../adr/0015-формат-фильтров-в-url.md)

## Цель

Продавец видит все позиции «товар × склад» с остатком, скоростью продаж и днями запаса, сразу понимает, сколько позиций в каждом статусе, и одним нажатием оставляет только нужный статус или находит товар по названию, артикулу или складу. Это продолжение блока «Скоро закончится» (spec 007): ссылка «Все остатки» ведёт сюда.

## Пользовательские сценарии

- Как продавец, я хочу видеть все остатки по складам, отсортированные от самых срочных, чтобы планировать поставки.
- Как продавец, я хочу одним нажатием оставить только «Критично» (или другой статус), чтобы не листать весь список.
- Как продавец, я хочу найти товар по названию, артикулу или складу.
- Как продавец, я хочу сузить остатки площадкой и категориями — теми же фильтрами, что на дашборде.
- Как продавец с телефона, я хочу видеть остатки карточками.

## Решения пользователя (2026-11-07)

1. **Все позиции одним запросом + виртуализация.** `/api/stocks` без `limit` отдаёт все позиции по площадке и категориям (сейчас ≈ 1000 — это агрегаты по паре «товар × склад», а не сырые записи). Таблица рисует только видимые строки — TanStack Virtual (выбран в ADR-0002; ставится в этой фиче, а не с «Заказами»).
2. **Поиск и плитки статусов — в браузере**, по уже загруженному списку: без новых запросов и без изменений API. Числа на плитках считаются с учётом поиска, как в макете.
3. **Статус и поиск — в состоянии страницы, не в URL**: при перезагрузке сбрасываются; формат URL (ADR-0015) не меняется.
4. **«Ничего не найдено»** (поиск или плитка дали 0 строк при непустых данных) — блок той же геометрии, что «пусто», со своим текстом (AC-19).

## Дизайн и адаптивность

- **Макет-референс:** `reference/Stock.dc.html` (раскладки `desktop` / `tablet` / `mobile`, состояния `data` / `loading` / `empty` / `error`, константы `L`), `DESIGN_SPEC.md` § 2, § 4 «Бейджи», «Таблица», «Мобильные карточки», § 5, § 6 «Остатки».
- **1440:** заголовок → 4 плитки в ряд с подсказкой порога → поиск + счётчик → таблица из 7 колонок (прокрутка внутри, до 620).
- **768:** плитки 4 в ряд без подсказок → поиск и счётчик в одном ряду → таблица из 5 колонок (строки 68, до 700).
- **375:** плитки 2 × 2 → поиск 44 → карточки + «Показать ещё».
- **Решения вне макета — на согласование вместе со spec:**
  - текст ошибки — «Проверьте соединение и повторите.» (как в spec 007): в макете пример про ключ Ozon, у нас такой причины нет;
  - «Показать ещё {k}» — k = min(20, оставшиеся) (AC-18): в макете кнопка пишет все оставшиеся («Показать ещё 900»), а добавляет 20 — текст обманывал бы;
  - «Ничего не найдено» (AC-19) — решение пользователя 4; иконка — лупа, как у поля поиска;
  - плитки и счётчик во время загрузки (скелетон числа) и при ошибке («—», счётчик скрыт) — в макете показаны только с данными (AC-20, AC-22);
  - подзаголовок до прихода `/api/meta` — скелетон, при ошибке meta — без даты (AC-4);
  - подсказки `title` у FBO / FBS — из макета; `title` виден только мышью, поэтому смысл схемы дублируется не им, а самим текстом FBO / FBS (как на дашборде).
- **Шапки с навигацией и нижних табов в этой фиче нет** (как и на дашборде): на «Остатки» попадают по ссылке «Все остатки», обратно — «Назад» браузера. Шапка — отдельная задача (см. «Открытые вопросы»).

## Данные и API

- `/api/stocks?mp&cat` (есть, spec 001) — без `limit`: все позиции по фильтрам, уже отсортированы. Поля: `asOf`, `total`, `counts`, `items[]` — `sku`, `name`, `offerId`, `marketplace`, `scheme`, `warehouse`, `category`, `stock`, `perDay`, `days | null`, `status`. Схема `stocksResponseSchema` (есть). Изменений API нет.
- `/api/meta` — `updatedAt` для подзаголовка (есть).
- Поиск, плитки, счётчики, «Показать ещё» — в браузере по загруженному списку (решение 2).

## Безопасность

- Ответ `/api/stocks` проверяется zod-схемой (`apiGet`); невалидный — состояние ошибки (AC-22).
- Поиск — только в памяти страницы: текст не уходит в URL, API и `localStorage`, не попадает в `RegExp` (сравнение подстрокой `includes`), выводится только как значение поля. Длина ввода ограничена `maxLength=100` (как `q` у `/api/orders`).
- Названия товаров и складов — текст React; `dangerouslySetInnerHTML` не используется.
- Новая зависимость `@tanstack/react-virtual` — из ADR-0002 (экосистема TanStack, без зависимостей кроме `@tanstack/virtual-core`); перед установкой — объяснение и согласие пользователя (AGENTS.md § 10).

## Не входит в задачу

- Шапка с навигацией, нижние табы, кнопка темы и «Экспорт в Excel».
- Экспорт остатков в Excel — фича 8.
- Плитка и поиск в URL (решение 3); смена сортировки пользователем.
- TanStack Table: колонки фиксированные, сортировки нет — хватит виртуализации; Table — вместе с «Заказами».
- Фото товаров, переход к товару.
- `document.title` по страницам — вместе с шапкой / 404.

## Открытые вопросы

- Ревью (`reviewer`): строка таблицы растёт по содержимому (`min-height` 52 / 68, как в макете) — виртуализатор измеряет фактическую высоту, иначе на 768 склад FBS с бейджами налезал на следующую строку; при смене плитки или поиска таблица прокручивается в начало (вне spec, очевидное поведение для списка «от самых срочных»). Не сделано (мелочи): шапка таблицы вне области прокрутки — при обычной полосе прокрутки Windows колонки тела сдвинуты на ширину полосы (так и в макете); число плитки 18/24 — без токена (в шкале его нет, как и других размеров компонентов); `formatAsOf` повторяет разбор `updatedAt` из `DashboardHeader` — вынести в `shared/lib` при следующем использовании; CSP — проверить консоль превью Vercel.

- ~~Вопросы `qa`~~ — решения пользователя 2026-11-07: скелетон до `/api/meta` заменяет всю строку (AC-4); плитки считаются по `items` (AC-7); поиск — по каждому полю отдельно, «ё» ≠ «е», при смене фильтров не сбрасывается (AC-8); счётчик «0» при «ничего не найдено» и пустом ответе (AC-9); кольцо фокуса у области прокрутки — ревью (AC-11). AC-8 исправлен по макету: на 640–1199 поле и счётчик в одном ряду (раньше в spec ошибочно «на всю ширину»).

- Шапки с навигацией нет в roadmap отдельным пунктом, а 404 (7a) её ждёт: добавить пункт «Шапка и нижние табы» в roadmap — решить при закрытии фичи.
