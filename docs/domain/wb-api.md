# Сверка с API Wildberries

- **Дата сверки:** 2026-11-05
- **Источник:** официальная документация [dev.wildberries.ru](https://dev.wildberries.ru/) — разделы «Аналитика и данные», «Финансы», «Отчёты», «Журнал изменений». Копии страниц, сохранённые в этот день, лежат локально в `docs/domain/sources/wb/` (в git не входят: чужие документы большого объёма). Сайт не открывается автоматическими инструментами (ответ 498), поэтому страницы сохранял пользователь вручную; схемы полей извлечены из встроенной в страницы OpenAPI-спецификации.
- **Решение:** [ADR-0010](../adr/0010-контракт-api-и-адаптеры.md). Глоссарий и формулы — [domain.md](../domain.md).

## Какие методы изображает генератор

В 2026 году WB переводит отчёты на новые методы. Генератор повторяет **новые**:

| Данные | Метод | Хост | Статус на 2026-11-05 |
|---|---|---|---|
| Заказы, выкупы, отмены, возвраты | `POST /api/analytics/v1/order-feed` («Лента заказов») | `seller-analytics-api.wildberries.ru` | новый (с 06.08.2026), заменяет `GET /api/v1/supplier/orders` и `GET /api/v1/supplier/sales` |
| Остатки на складах WB | `POST /api/analytics/v1/stocks-report/wb-warehouses` | `seller-analytics-api.wildberries.ru` | новый, заменил `GET /api/v1/supplier/stocks` |
| Деньги: цена продажи, комиссия, логистика, к перечислению | `POST /api/finance/v1/sales-reports/detailed` («Детализации к отчётам реализации за период») | `finance-api.wildberries.ru` | новый, заменил `GET /api/v5/supplier/reportDetailByPeriod` (отключён 15 июля 2026) |

Старые `supplier/orders` и `supplier/sales` пока работают, но WB предупредил об отключении в будущем (журнал изменений, 06.08.2026) — поэтому не используются.

## Поля, которые использует генератор

### Лента заказов — `data.orders[]`

«1 заказ = 1 сборочное задание = 1 единица товара». Отдаёт заказы максимум за 31 день, по времени текущего статуса.

| Поле | Тип | Смысл по документации |
|---|---|---|
| `srid` | string | ID заказа; связывает заказ со строками отчёта реализации |
| `nmId` | int64 | артикул WB |
| `chrtId` | uint64 | ID размера |
| `createdAt` | date-time, `+03:00` | дата и время оформления заказа |
| `updatedAt` | date-time, `+03:00` | дата и время текущего статуса (при `created` = `createdAt`) |
| `status` | enum | `created` — оформлен, `buyout` — продан, `cancel` — отменён, `return` — возвращён, `returnDefective` — возвращён по причине брака |
| `cancelType` | enum, только при `cancel` | `app` — отказ до получения, `receipt` — отказ при получении, `expire` — истёк срок получения, `other` |
| `warehouseName` | string | название склада |
| `warehouseRegion` | string | федеральный округ склада |
| `isMp` | boolean | `true` — склад продавца, `false` — склад WB |
| `destinationCity`, `destinationDistrict` | string | куда доставляется |
| `sellerPrice` | float64 | цена продавца со скидкой продавца (без скидки WB Клуба и оптовой скидки B2B) |
| `isB2b` | boolean | B2B-продажа |

Обёртка: `data.snapshotTime`, `data.currency` (`RUB`), `data.orders`.

### Остатки на складах WB — `data.items[]`

Одна строка — один размер товара на одном складе. Обновляется раз в 30 минут.

| Поле | Тип | Смысл |
|---|---|---|
| `nmId` | int64 | артикул WB |
| `chrtId` | uint64 | ID размера |
| `warehouseId` | int64 | ID склада |
| `warehouseName` | string | название склада |
| `regionName` | string | страна отгрузки |
| `quantity` | uint64 | доступно покупателям для добавления в корзину |
| `inWayToClient` | uint64 | в пути к клиенту |
| `inWayFromClient` | uint64 | в пути от клиента (возвраты) |

### Детализация отчёта реализации — строки ответа

Метод возвращает ~100 полей; суммы — **строки** (`"376.99"`), проценты — числа. Используются:

| Поле | Тип | Смысл |
|---|---|---|
| `srid` | string | ID заказа (связь с лентой заказов) |
| `nmId`, `vendorCode`, `title`, `subjectName`, `brandName` | — | артикул WB, артикул продавца, название, предмет, бренд |
| `docTypeName` | string | тип документа: «Продажа», «Возврат» |
| `sellerOperName` | string | обоснование для оплаты: «Продажа», «Возврат», «Логистика» и др. |
| `quantity` | int | количество |
| `retailPriceWithDisc` | string | цена розничная с учётом согласованной скидки |
| `forPay` | string | к перечислению продавцу за реализованный товар |
| `commissionPercent` | number | размер кВВ, % |
| `deliveryService` | string | услуги по доставке товара покупателю (логистика) |
| `deliveryAmount`, `returnAmount` | int | количество доставок и возвратов в строке логистики |
| `officeName` | string | склад |
| `orderDt`, `saleDt` | date-time (фактически дата: `"2026-03-21T00:00:00Z"`) | дата заказа и продажи |
| `rrDate` | date | дата операции |
| `rrdId` | int | ID строки (пагинация) |

## Соответствие доменной модели

Правила учёта и формулы — [domain.md](../domain.md) («Два правила учёта»). Каждая строка ниже проверяется тестом адаптера (AC-9).

| Доменное поле | Откуда у WB | Правило |
|---|---|---|
| площадка | — | всегда `wb` |
| схема FBO/FBS | — | `null`. Это решение продукта под макеты (схема показывается только у Ozon), а не свойство API: у WB есть `isMp`; генератор всегда ставит `isMp = false` (склад WB) |
| ID заказа | `srid` | как есть |
| артикул площадки | `nmId` | число → строка (`47254354` → `"47254354"`) |
| артикул продавца, название, категория, себестоимость | справочник продавца в нашем BFF, по `nmId` | в ленте заказов этих полей нет; категория — наша (8 категорий), а не `subjectName` WB |
| склад | `warehouseName` | как есть, без преобразований (см. «Расхождения») |
| дата и время заказа | `createdAt` | уже по Москве (`+03:00`), переводить не нужно |
| цена заказа (заказы ₽) | `sellerPrice` ленты | число |
| цена выкупа и возврата (выручка) | `retailPriceWithDisc` строки «Продажа» / «Возврат» | строка → число (`"399.68"` → `399.68`) |
| итог «в пути» | `status = created` | строк отчёта реализации нет |
| итог «выкуплен» | `status = buyout` | |
| выкуп и его дата | строка отчёта с `docTypeName = «Продажа»` **и** `sellerOperName = «Продажа»` и тем же `srid`; дата — `saleDt` (у строк логистики `docTypeName` тоже «Продажа», их отличает `sellerOperName = «Логистика»`) | у каждого заказа со статусом `buyout`, `return` или `returnDefective` есть ровно одна строка «Продажа» (гарантия генератора) |
| итог «отменён» и дата отмены | `status = cancel`; дата — `updatedAt` | все виды `cancelType` — отмена; `app` — до отправки (логистики нет), `receipt` и `expire` — товар ехал к покупателю (доставка и обратная доставка) |
| итог «возвращён» и дата возврата | `status = return` или `returnDefective`; дата — `saleDt` строки отчёта с `docTypeName = «Возврат»` | оба статуса — возврат; дата берётся только из отчёта, `updatedAt` ленты не используется |
| комиссия выкупа | `retailPriceWithDisc − forPay` строки «Продажа» | всё, что WB удержал из цены (кВВ, эквайринг) |
| комиссия возврата (возвращается продавцу) | `retailPriceWithDisc − forPay` строки «Возврат» | |
| доставка к покупателю | `deliveryService` строки `sellerOperName = «Логистика»` с `deliveryAmount = 1`; дата — `rrDate` | строка → число |
| обратная доставка | `deliveryService` строки «Логистика» с `returnAmount = 1`; дата — `rrDate` | |
| остаток | `quantity`, сумма по `chrtId` товара на складе | `inWayToClient` / `inWayFromClient` в остаток не входят |

**Даты.** `createdAt` и `updatedAt` — момент времени с `+03:00`, день по Москве берётся из него как есть. `saleDt` и `orderDt` в отчёте реализации — календарная дата в виде `2026-03-21T00:00:00Z`: берётся часть `ГГГГ-ММ-ДД` как есть, **без перевода** часового пояса. `rrDate` — `ГГГГ-ММ-ДД`.

## Расхождения и допущения

- **Склады WB по названиям.** С 15 августа 2026 WB временно не показывает разбивку по своим складам в РФ: в остатках вместо них — суммарные строки «Склад WB РФ» / «Склад WB СГТ РФ» (отдельно остаётся Коледино), в ленте заказов — «Склад WB». Генератор, как в макетах дизайна, использует склады по названиям (Коледино, Электросталь, Подольск, Казань, Краснодар, Екатеринбург, Тула, Новосибирск) — как WB отдавал до 15.08.2026. Решение пользователя от 2026-11-05.
- **Склады WB в генераторе:** Коледино, Электросталь, Подольск, Казань, Краснодар, Екатеринбург, Тула, Новосибирск — одинаковые названия в ленте заказов, остатках и `officeName` отчёта.
- **Одна цена.** В реальных данных `sellerPrice` ленты и `retailPriceWithDisc` отчёта могут расходиться (скидки WB Клуба, промокоды). Генератор делает их равными — так заказы ₽ и выручка сопоставимы. Это допущение генератора, адаптер берёт каждое поле из своего источника.
- **Набор значений.** Генератор создаёт только перечисленные статусы и `cancelType`, строки отчёта только с `docTypeName` «Продажа» / «Возврат» и `sellerOperName` «Продажа» / «Возврат» / «Логистика». Сырая zod-схема принимает все значения enum из документации; адаптер на незнакомом значении бросает ошибку (лучше заметить, чем тихо посчитать неверно).
- **Одна строка отчёта на событие.** Настоящий отчёт реализации формируется раз в день/неделю и содержит корректировки, штрафы, хранение. Генератор создаёт только строки «Продажа», «Возврат» и «Логистика» — остального нет в формуле прибыли ([domain.md](../domain.md)).
- **Глубина истории.** Лента заказов отдаёт только последние 31 день; реальный BFF копил бы историю у себя. Генератор сразу создаёт 24 месяца — так, будто BFF работает давно.
- **Размеры.** `chrtId` генерируется, но остатки и метрики считаются по товару целиком (сумма по размерам) — в макетах размеров нет.
- **Валюта** — только `RUB`, B2B-продажи (`isB2b`) не генерируются.
