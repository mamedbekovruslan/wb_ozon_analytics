# 0011. Роли ИИ: основной агент и два субагента

- **Статус:** принято
- **Дата:** 2026-11-04

## Контекст

Код пишет ИИ. Агент, написавший код, хуже находит в нём ошибки, а длинные проверки засоряют его контекст. Нужно независимое ревью и тесты, не подогнанные под реализацию, без лишней бюрократии.

## Рассмотренные варианты

1. Всё в одном чате без ролей — дёшево, но нет независимого взгляда.
2. Отдельные чаты под роли — контекст теряется между чатами, пользователь вручную переносит информацию.
3. Один основной агент + субагенты в `.claude/agents/` — роли вызываются автоматически на контрольных точках, работают в чистом контексте, возвращают только вывод.

## Решение

Вариант 3, две роли:
- `qa` — после согласования spec пишет тесты по критериям приёмки, не видя реализации;
- `reviewer` — перед показом коммита пользователю проверяет FSD, конвенции, читаемость и безопасность (skill `security-check`).

Сверка API WB/Ozon — разовая задача встроенного агента, отдельная роль не нужна. Новая роль заводится только под конкретную проблему, через новый ADR. Субагенты не коммитят; правило ручной проверки коммитов (AGENTS.md, раздел 6) действует на всё.

## Последствия

- Независимые тесты и ревью на каждой фиче.
- Каждый вызов субагента стоит дополнительных токенов и времени.
