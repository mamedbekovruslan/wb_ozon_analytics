# 0009. Стратегия тестирования

- **Статус:** принято
- **Дата:** 2026-11-04

## Контекст

Код пишут в основном ИИ-агенты, а ошибки в формулах метрик (прибыль, % выкупа, дни запаса) напрямую вводят продавца в заблуждение. Тесты — главная страховка от ошибок агента. Решение пользователя: тесты обязательны для каждой фичи.

## Решение

Четыре уровня:

| Уровень | Инструмент | Что проверяет |
|---|---|---|
| Статика | `tsc`, oxlint, steiger | типы, стиль, границы FSD |
| Unit | Vitest | формулы метрик, форматтеры ru-RU, zod-схемы, экранирование для Excel, детерминизм генератора, адаптеры, агрегации |
| Интеграционные | Vitest + Testing Library + MSW | состояния виджетов (загрузка / пусто / ошибка / данные), реакция на смену фильтров |
| E2E | Playwright | 5–7 сценариев в браузере: фильтры и URL, F5, экспорт, 375 px, тёмная тема, доступность (axe-core) |

Пакеты (только dev): `jsdom` — среда Vitest по умолчанию (тест без DOM помечается `// @vitest-environment node`); `@testing-library/react`, `@testing-library/dom`, `@testing-library/user-event`, `@testing-library/jest-dom`; `@playwright/test` (Chromium, 1440 и 375 px, по собранной версии); `@axe-core/playwright` — вместе с задачей a11y. Интеграционные тесты поднимают `msw/node` с обработчиками из `mocks/handlers` — это единственное разрешённое использование `mocks/` вне `app/`.

Дополнительно: `vitest bench` для генерации и агрегации (< 100 мс на запрос).

Правила:
- каждый критерий приёмки из spec покрыт хотя бы одним тестом;
- тесты пишет субагент `qa` по spec до реализации ([ADR-0011](0011-роли-ии.md));
- покрытие ≥ 80% для `entities`, `shared/lib`, `mocks`; для UI процент не гонится;
- после подключения CI падение тестов блокирует слияние в `main`.

## Последствия

- Фича пишется дольше, но регрессии ловятся автоматически.
- Детерминированные данные (seed) делают тесты и скриншоты стабильными.
