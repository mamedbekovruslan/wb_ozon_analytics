# 0015. Формат фильтров в URL

- **Статус:** принято
- **Дата:** 2026-11-06

Дополняет [ADR-0007](0007-роутинг-и-фильтры-в-url.md): там решено хранить фильтры в URL, здесь — как именно. Реализация — [spec 002](../specs/002-фильтры-в-url.md).

## Контекст

- Пресеты периода («30 дней», «Квартал») зависят от «сегодня», а оно приходит из `/api/meta` асинхронно. Ссылка «последние 30 дней» должна оставаться актуальной завтра, а свой период — фиксированным.
- TanStack Router по умолчанию пишет значения в URL как JSON (`?mp=%22wb%22`, `?cat=%5B%22shoes%22%5D`), а контракт API (spec 001) — повторяющийся `?cat=shoes&cat=sports`.
- Мусор в URL не должен ломать страницу (T4) и не должен оставаться в адресе и в истории «Назад».
- Фильтры общие для всех страниц.
- В макете период заканчивается вчерашним днём: данные за сегодня неполные.
- steiger (`fsd/insignificant-slice`) считает ошибкой фичу, которую использует только один срез.

## Рассмотренные варианты

1. **Всегда даты** `?from=…&to=…` (пример из ADR-0007) — один формат, но ссылка «последние 30 дней» навсегда застывает на конкретных датах, а выбранный пресет приходится угадывать по совпадению дат.
2. **Пресет или даты**: `?period=7|90|q|y` для пресетов, `?from=…&to=…` для своего периода — ссылка с пресетом относительна, свой период точен; цена — два способа задать период и правило приоритета.
3. Формат JSON по умолчанию TanStack Router — без своего кода, но адрес нечитаем и не совпадает с параметрами API.

Для UI-контролов фильтров:

1. По фиче на контрол (`features/filter-period`, `filter-marketplace`, `filter-category`) + виджет — как в первоначальном списке AGENTS.md; steiger: 4 ошибки `insignificant-slice` и `repetitive-naming`, исключение навсегда.
2. Всё в `widgets/filter-bar` — контролы нужны только этой панели; одно временное предупреждение, пока панель стоит на одной странице.

## Решение

Вариант 2 для формата и вариант 2 для контролов:

- параметры: `period` (`7`, `90`, `q`, `y`), `from` + `to` (`ГГГГ-ММ-ДД`), `mp` (`wb`, `ozon`), `cat` (повторяется, порядок справочника), `cmp=0`; значения по умолчанию (30 дней, все площадки, все категории, сравнение включено) в URL не пишутся;
- валидный свой период вытесняет `period`; невалидный — удаляется, действует `period` или 30 дней;
- пресеты заканчиваются вчера: `q` — с начала квартала, `y` — с 1 января; начало не раньше `historyFrom`;
- свои `parseSearch` / `stringifySearch` (`shared/api/filters`): текст, а не JSON; ключ `__proto__` не подменяет прототип;
- фильтры проверяются на корневом маршруте; адрес приводится к чистому виду заменой записи истории — сразу (формат) и после `/api/meta` (даты по смыслу). Роутер кладёт проверенные значения поверх сырых, поэтому чистый вид считается заново через `parseFiltersSearch`;
- чтение и запись фильтров — только через хуки `shared/lib` (`useFiltersSearch`, `useSetFiltersSearch`) и `entities/marketplace` (`useFilters`); формат адреса задан в одном месте;
- контролы — внутри `widgets/filter-bar`, отдельных фич нет.

## Последствия

- Ссылки читаемы и совпадают с параметрами `/api/...`; `toApiParams` строит запрос из разрешённых фильтров.
- Мусор в URL исправляется молча, «Назад» к нему не возвращает.
- Даты периода известны только после `/api/meta`: до этого блоки показывают скелетоны.
- Новая страница со своими параметрами (например, поиск на «Заказах») должна сохранять фильтры: корневая очистка URL сейчас удаляет всё, кроме параметров фильтров, — учесть в фиче «Страница заказов».
- Правило steiger для `widgets/filter-bar` временно понижено до предупреждения; вернуть ошибку, когда панель встанет на вторую страницу.
