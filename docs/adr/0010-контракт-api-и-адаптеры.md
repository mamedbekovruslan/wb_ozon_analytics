# 0010. Контракт API и адаптеры WB/Ozon

- **Статус:** принято
- **Дата:** 2026-11-04

## Контекст

Данные должны быть максимально похожи на реальные данные WB и Ozon, а переход на реальные API в будущем — не требовать переписывания интерфейса. Доступа к реальному кабинету продавца нет: опираемся на официальную документацию.

Браузер не может обращаться к API WB/Ozon напрямую: нужен секретный токен продавца, есть ограничения CORS и лимиты частоты запросов. В реальном продукте между браузером и площадками стоит собственный backend (BFF).

## Решение

```
Браузер ──► наш BFF (/api/...) ──► API WB / API Ozon
            └─ сейчас его изображает MSW
```

Внутри фейкового BFF (`src/mocks/`) три слоя:
1. **Генератор** создаёт «сырые» записи в форме ответов реальных API: WB — Statistics API (заказы, продажи, остатки) и отчёт реализации (комиссии, логистика); Ozon — Seller API (отправления FBO/FBS, аналитика, остатки по складам, финансовые операции).
   Уточнено 2026-11-05 по сверке ([spec 001](../specs/001-фейковый-api.md)): площадки сменили методы. WB — «Лента заказов» `order-feed` и остатки `stocks-report/wb-warehouses` (Analytics API) вместо `supplier/*`, детализация отчёта реализации `sales-reports/detailed` (Finance API); Ozon — `/v3/posting/fbo/list`, `/v4/posting/fbs/list`, `/v1/returns/list`, начисления `/v1/finance/accrual/by-day`, остатки `/v1/analytics/stocks` и `/v1/product/info/warehouse/stocks`. Подробности — [domain/wb-api.md](../domain/wb-api.md), [domain/ozon-api.md](../domain/ozon-api.md).
2. **Адаптеры** `wbAdapter` / `ozonAdapter` приводят сырые данные к единой доменной модели.
3. **Агрегаторы** считают метрики и отдают их по нашему контракту `/api/...`.

Контракт `/api/...` описан zod-схемами в `entities/*` и проверяется на клиенте. Общие примитивы контракта, которые нужны схемам нескольких сущностей (дата, момент времени, площадка, категория, FBO/FBS), лежат в `shared/api/contract.ts`: это формат ответа API, а не бизнес-логика, и так слайсы `entities` не импортируют друг друга (уточнено 2026-11-05, spec 001).

Перед реализацией генератора — сверка с актуальной документацией (dev.wildberries.ru, docs.ozon.ru) с фиксацией в `docs/domain/wb-api.md` и `docs/domain/ozon-api.md` (дата, ссылки, поля). Расхождения и допущения записываются туда же. В README прямо указано, что данные синтетические.

## Последствия

- Переход на реальные API = заменить генератор HTTP-клиентом в настоящем BFF; адаптеры, агрегаторы и UI остаются.
- Форма данных зависит от актуальности документации площадок, которые часто меняют API, — сверка датируется.
