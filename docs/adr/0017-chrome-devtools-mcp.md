# 0017. Chrome DevTools MCP для проверки в браузере

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

Агент проверяет вёрстку, консоль (ошибки CSP) и производительность только через код и тесты. Скриншоты на 375 и 1440 px, обе темы и замеры (например, тормоза тултипа графика продаж) пользователь делает руками и пересказывает. Это медленно, и результаты зависят от того, что пользователь успел заметить. Агенту нужен свой браузер: открыть страницу, посмотреть DOM и консоль, сделать скриншот, записать профиль производительности.

## Рассмотренные варианты

1. **Оставить как есть** — пользователь сам проверяет в браузере. Ничего не ставится, но цикл «правка → проверка» длинный, а замеры «до/после» не воспроизводятся.
2. **Playwright-скрипты по запросу** — Playwright уже есть, но тогда на каждую проверку пишется и запускается одноразовый скрипт. Это неудобно, а профиль производительности получается неполным.
3. **Chrome DevTools MCP** (`chrome-devtools-mcp`, официальный пакет команды Chrome) — MCP-сервер, через который агент управляет отдельным Chrome: навигация, скриншоты, DOM-снимок, консоль, сеть, эмуляция размеров и темы, трассировка производительности. Пакет публикуется из GitHub Actions с SLSA provenance.

## Решение

Вариант 3. Конфигурация — в `.mcp.json` в корне репозитория:
- версия закреплена точно (`chrome-devtools-mcp@1.12.0`, вышла 2026-10-22), без `@latest`; проверка обновлений отключена (`CHROME_DEVTOOLS_MCP_NO_UPDATE_CHECKS`), версию повышаем вручную;
- `--isolated` — временный профиль Chrome, без доступа к обычному профилю пользователя (cookies, пароли), удаляется после закрытия;
- `--no-usage-statistics` — не отправлять в Google статистику использования (по умолчанию включена);
- `--no-performance-crux` — не отправлять адреса страниц в CrUX API при анализе производительности;
- запуск через `cmd /c npx` — так Claude Code запускает `npx` на Windows.

Права в `.claude/settings.json` (решение пользователя). Правило `ask` важнее `allow`, поэтому весь сервер разрешён, а исключения требуют подтверждения:

| Без спроса | С подтверждением |
|---|---|
| скриншоты, DOM-снимок, клики и ввод, наведение, клавиши, размер окна и эмуляция (тема, сеть, viewport), консоль, сеть, трассировка производительности, Lighthouse, анализ снимков памяти | открыть адрес — `navigate_page`, `new_page`; выполнить JS — `evaluate_script`, `set_logpoints`; загрузить файл — `upload_file`; всегда пишут файл — `take_heapsnapshot`, `screencast_start` |

Открытие адреса стоит на подтверждении, потому что технически закрыть адреса `file://` флагами Chrome надёжно нельзя. Без подтверждения агент мог бы открыть `.env` как страницу и обойти запрет на его чтение (правило 4), в том числе под влиянием текста на открытой странице (prompt injection). С подтверждением пользователь видит каждый адрес и параметры вызова, включая `initScript` у `navigate_page`. Открываются только `localhost` и превью/продакшен Vercel этого проекта. Параметр `filePath` у скриншота, DOM-снимка и трассировки указывает только во временную папку агента: запретить его отдельно от инструмента нельзя, это договорённость.

Пакет не входит в `package.json` и не влияет на сборку, CI и деплой. У версии 1.12.0 нет внешних зависимостей (`npm view … dependencies` пуст), поэтому закреплённая версия фиксирует весь скачиваемый код. У пакета есть SLSA provenance.

## Последствия

- Правило проекта 9 (AGENTS.md, раздел 13) закрепляет эти права.

- Агент сам делает скриншоты, смотрит консоль и снимает профили «до/после» для задач вроде тормозов тултипа.
- Нужен установленный Google Chrome. При первом запуске Claude Code спрашивает, доверять ли серверу из `.mcp.json`.
- Риск: код пакета скачивается из npm при запуске, мимо lockfile и Dependabot. Он снижен закреплённой версией без внешних зависимостей и provenance. Новую версию ставим после проверки changelog и не раньше чем через две недели после выхода. При повышении сверяем список инструментов с правами `ask`: если имя инструмента изменилось, правило молча перестаёт работать (чек-лист в [security.md](../security.md), угроза T10).
- Содержимое открытых страниц попадает в контекст агента, поэтому в этом браузере не открываются сайты с личными данными.
