# 0003. Архитектура frontend — Feature-Sliced Design

- **Статус:** принято
- **Дата:** 2026-11-04

## Контекст

Нужна понятная структура, которую одинаково соблюдают человек и ИИ-агенты, с автоматической проверкой границ. Проект ориентирован на российский рынок, где FSD широко распространён и узнаётся заказчиками и тимлидами.

## Рассмотренные варианты

1. Папки по типам (`components/`, `hooks/`, `utils/`) — просто, но быстро превращается в свалку, границ нет.
2. Папки по фичам без строгих правил — лучше, но правила держатся только на дисциплине.
3. Feature-Sliced Design — стандартизированные слои, правило импортов, линтер `steiger`.

## Решение

FSD со слоями `app → pages → widgets → features → entities → shared`. Импорт только сверху вниз, доступ к слайсу только через `index.ts`. Дополнительно — `src/mocks/` как изолированный фейковый backend (см. [ADR-0004](0004-msw-и-генератор-данных.md)). Границы проверяет `steiger` (устанавливается на этапе 1).

## Последствия

- Агент не может незаметно нарушить архитектуру: steiger упадёт.
- Больше файлов `index.ts` и немного церемоний для маленьких сущностей.
- Структура слоёв описана в AGENTS.md, раздел 4.
