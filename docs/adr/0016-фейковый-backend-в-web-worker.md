# 0016. Фейковый backend в Web Worker

- **Статус:** принято
- **Дата:** 2026-11-06

## Контекст

По [ADR-0004](0004-msw-и-генератор-данных.md) генерация, которая блокирует основной поток дольше 100 мс, выносится в Web Worker. Замер ([spec 001](../specs/001-фейковый-api.md), «Замеры»): первая генерация с адаптерами — ~2,7 с, эндпоинты на готовых данных — 11–77 мс. Всё это время вкладка не отвечает.

MSW в браузере выполняет обработчики в основном потоке: Service Worker только пересылает запрос во вкладку. Поэтому перенести в фон одну генерацию мало.

## Рассмотренные варианты

1. **Генерация в воркере, данные передаются во вкладку.** Структурное копирование ~100 тыс. заказов само блокирует поток на сотни миллисекунд, а агрегаты (до ~80 мс на запрос) по-прежнему считаются во вкладке.
2. **Весь фейковый backend в воркере, MSW только пересылает запросы.** Данные не покидают воркер, во вкладку идут только готовые JSON-ответы — так же, как с настоящим сервером. Нужен небольшой протокол сообщений.
3. **Нарезать генерацию на куски (`setTimeout`/`scheduler.yield`).** Вкладка «дышит», но общая работа остаётся в основном потоке и удлиняется, а код генератора усложняется.
4. **Библиотека-обёртка (Comlink).** Удобнее вызов, но это новая зависимость ради трёх типов сообщений.

## Решение

Вариант 2. Логика фейкового BFF выделена в ядро `createApiCore` — функцию «путь + параметры → статус + JSON», независимую от транспорта ([spec 003](../specs/003-генерация-в-фоне.md)):

- в браузере ядро работает в выделенном модульном воркере (`new Worker(new URL(...), { type: 'module' })`, средства Vite, без новых зависимостей); MSW-обработчики `createWorkerHandlers` пересылают запрос и отдают ответ;
- «сейчас» передаётся воркеру из основного потока при старте; генерация начинается сразу, не дожидаясь первого запроса;
- падение воркера превращается в 500 с понятным текстом, запросы не зависают;
- в Node-тестах ядро работает в том же потоке через прежний `createHandlers` — тесты API не зависят от воркера;
- воркер — отдельный файл сборки с того же домена: CSP `worker-src 'self'` не ослабляется.

## Последствия

- Вкладка отзывчива во время генерации; агрегаты тоже не нагружают основной поток.
- Ядро — то же «запрос → ответ», что у будущего настоящего backend; убрать MSW по-прежнему можно без изменений UI.
- Появляется протокол сообщений и ещё один файл сборки; ответы воркера проверяются zod.
- Отладка генератора в браузере — через DevTools воркера, а не вкладки.
- У воркера своя копия zod: её, как и zod вкладки, нужно перевести в режим `jitless` первым импортом точки входа, иначе CSP фиксирует попытку `new Function` (spec 003, «Безопасность»).
- Неизвестный `GET /api/...` в браузере теперь получает честный 404 от ядра, а не предупреждение MSW о необработанном запросе.
- Таймаута ответа воркера нет: если воркер зависнет, не упав, запросы будут ждать. Пока недостижимо (протокол формирует наш код) — открытый вопрос в roadmap.
