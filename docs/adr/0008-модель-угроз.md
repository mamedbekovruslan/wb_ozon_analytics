# 0008. Модель угроз и базовые меры безопасности

- **Статус:** принято
- **Дата:** 2026-11-04

## Контекст

Сейчас это фронтенд без собственного сервера, на синтетических данных — поверхность атаки небольшая. Но продукт рассчитан на подключение реальных API WB/Ozon с токенами продавца, а экспорт в Excel открывает реальный вектор атаки. Решения по безопасности нужно принять заранее, чтобы не переделывать архитектуру.

## Решение

Полная модель угроз и чек-лист — в [docs/security.md](../security.md). Ключевые решения:
- токены WB/Ozon хранятся только на backend (BFF), никогда в браузере; всё с префиксом `VITE_*` считается публичным;
- все внешние данные (URL, ответы API) проходят zod-валидацию;
- `dangerouslySetInnerHTML` запрещён;
- экспорт в Excel экранирует ячейки от formula injection;
- заголовки безопасности (CSP и др.) задаются в `vercel.json`;
- зависимости контролируются: lockfile, `npm audit`, gitleaks, Dependabot (подключаются с согласия пользователя, правило 1 в AGENTS.md);
- новая зависимость — только через ADR.

## Последствия

- Архитектура сразу готова к реальным токенам без переделки.
- Чек-лист безопасности проверяет субагент `reviewer` (skill `security-check`).
