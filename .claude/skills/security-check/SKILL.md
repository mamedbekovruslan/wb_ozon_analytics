# Проверка безопасности

1. Прочитать `docs/security.md` — таблицу угроз T1–T9 и чек-лист.
2. Получить список изменений: `git diff main...HEAD --stat` и `git diff main...HEAD` (плюс незакоммиченные: `git diff`, `git status`).
3. Пройти чек-лист по каждому изменённому файлу. Для каждой затронутой угрозы проверить, что мера применена:
   - T1 секреты: поиск `token`, `secret`, `password`, `apiKey`, `Authorization`, `VITE_` в изменениях;
   - T2 экспорт: все строковые ячейки проходят функцию экранирования, есть тест на `=1+1`, `+`, `-`, `@`;
   - T3 XSS: нет `dangerouslySetInnerHTML`, `eval`, `new Function`, `innerHTML`;
   - T4/T5 валидация: новые параметры URL и ответы API описаны zod-схемами;
   - T7/T8 зависимости: изменения `package.json` сопровождаются ADR; нет пакета `xlsx`;
   - T9 хранилище: `localStorage`/`sessionStorage` используются только для темы.
4. Результат — список находок с уровнем: **блокер** (нарушена мера из таблицы), **важно**, **замечание**. Для каждой — файл, строка, в чём риск, как исправить.
5. Если находок нет — явно написать «Проверено по T1–T9, нарушений не найдено» и перечислить, какие угрозы были затронуты изменениями.
